## Context

The codebase has two categories of dead scaffolding:

1. **Fumadocs** — `fumadocs-core`, `fumadocs-mdx`, `fumadocs-ui` are installed. The `RootProvider` from `fumadocs-ui/provider/tanstack` wraps the entire app in `__root.tsx`. Generated files exist in `apps/web/.source/` and MDX content lives in `apps/web/src/changelog/`. However, no `/docs` route was ever implemented, so fumadocs is active infrastructure serving zero pages.

2. **AI/Chat** — Cloudflare agents framework (`agents`), Vercel AI SDK (`ai`), `@cloudflare/ai-chat`, and `workers-ai-provider` are installed in both `apps/api` and `apps/web`. The implementation (`chat.agent.ts`, chat route files, `chat-room.tsx` server function) was built and then deleted — leaving the API entry point (`apps/api/src/index.ts`) with broken imports and a dead `/agents/*` route handler. A WebSocket proxy for `/agents` also remains in the Vite config.

## Goals / Non-Goals

**Goals:**

- Remove all three fumadocs packages and their generated artifacts from `apps/web`
- Remove `RootProvider` from `__root.tsx` without changing any routing or layout behavior
- Remove the four AI/chat packages from `apps/api` and three from `apps/web`
- Clean up `apps/api/src/index.ts` to remove the broken `ChatAgent` import and dead agent route
- Remove the `/agents` proxy from `apps/web/vite.config.ts`
- Stage and commit the already-deleted chat files (currently unstaged) as part of this cleanup
- Delete `apps/web/src/changelog/` and `apps/web/.source/` directories

**Non-Goals:**

- No changes to any user-facing functionality
- No changes to auth, payment, template, or showcase logic
- No changes to the `ai-agents-section.tsx` homepage component (marketing copy, not chat feature)
- No introduction of replacement documentation infrastructure

## Decisions

### D1: Delete `.source/` directory entirely

The `.source/` directory is auto-generated by `fumadocs-mdx` during build. It is safe to delete — it will not be regenerated once the package is removed. It is in `.gitignore` or equivalent generated-output patterns; if not, we delete it and it stays gone.

### D2: Remove `RootProvider` wrapper without replacement

`RootProvider` from fumadocs-ui adds context for search, TOC, and theme that no page currently consumes. Removing it leaves the app with no behavioral change. No replacement provider needed.

### D3: Stage existing deletions as part of this change

The chat files (`apps/api/src/agents/chat.agent.ts`, `apps/web/src/routes/(app)/_app/chat/*`, `apps/web/src/routes/-fn/chat-room.tsx`) are already deleted in the working tree but unstaged. This change includes staging them so the repository state is consistent — no partial-deletion artifacts left behind.

### D4: Clean `apps/api/src/index.ts` imports surgically

Only remove the `ChatAgent` import, `routeAgentRequest` import, and the `/agents/*` route handler block. Leave all other middleware, routing, and error handling intact.

## Risks / Trade-offs

- **`pnpm-lock.yaml` changes** → Mitigation: `pnpm install` after package.json edits regenerates the lockfile cleanly; commit together.
- **`.source/` may be gitignored** → Check first; if not tracked, `git rm -r` it; if gitignored, just delete from filesystem.
- **`apps/web/src/changelog/` content loss** → Acceptable: no page renders this content; the MDX files serve no users.
- **Breaking TypeScript if fumadocs types are referenced elsewhere** → Mitigation: after removal, run a type check pass to catch any stray imports.
